Universal Map2web

Version : 1.4.0 | QGIS : 3.0+

Extension QGIS pour exporter des couches vectorielles en cartes HTML interactives avec préservation de la symbologie QGIS.

Fonctionnalités

  • Export multi-couches avec styles QGIS (couleurs, épaisseurs, opacités)
  • Conservation des étiquettes (labeling) et légende automatique
  • Fonds de plan : OSM, Google Satellite, Hybrid ou personnalisé
  • Outils : géolocalisation, mesure, recherche, plein écran, minimap, impression
  • Filtrage avancé par attribut (8 opérateurs)
  • 4 thèmes visuels : Clair, Sombre, Professionnel, Coloré
  • Regroupement des points (clustering)
  • Configuration des popups par couche
  • Mode PostgreSQL/PostGIS dynamique (données en direct au lieu d'un export figé)
  • Fenêtre de table attributaire pour chaque couche vectorielle (tri, filtre, recherche, surbrillance sur la carte, export CSV)
  • Bouton « Zoom sur la couche »
  • Couches WFS (vecteur) et WMS (raster) en direct depuis GeoServer / serveurs OGC

Manuel rapide

1. Lancement

Cliquez sur l'icône Universal Map2web dans la barre d'outils QGIS.

2. Export

  1. Sélectionnez les couches à exporter (onglet Couches)
  2. Configurez les popups (champs à afficher au clic)
  3. Activez éventuellement le mode PostgreSQL/PostGIS dynamique pour les couches connectées à une base
  4. Choisissez le fond de plan et le thème
  5. Personnalisez : titre, logo, couleur d'en-tête
  6. Activez les outils souhaités
  7. Cliquez sur "OK" et choisissez le dossier de destination
  8. La carte s'ouvre automatiquement dans le navigateur

3. Navigation web

Action Commande
Zoom Molette / + / -
Déplacer Clic-glisser
Voir attributs Clic sur l'élément
Ouvrir la table attributaire Clic sur l'icône de table devant le nom de la couche
Zoom sur la couche Clic sur l'icône loupe devant le nom de la couche
Réinitialiser vue Double-clic sur la carte

4. Filtrage avancé

Dans la barre latérale de la carte : sélectionnez couche → champ → opérateur → saisissez la valeur → Appliquer.

Opérateurs disponibles : = ≠ contient commence par > < ≥ ≤

5. Gestion des couches sur la carte

  • Afficher/Masquer : cocher/décocher dans la légende
  • Clustering : activer "Regrouper les points" (couches ponctuelles)
  • Légende : affichage automatique des catégories et couleurs

6. Mode PostgreSQL dynamique

Pour les couches déjà connectées à PostgreSQL/PostGIS dans QGIS, activez « Charger dynamiquement les couches PostGIS depuis PostgreSQL (au lieu d'un export figé) » dans la boîte de dialogue.

  • La connexion QGIS existante est réutilisée : aucun identifiant à ressaisir dans le plugin
  • Un point d'accès protégé get_data.php et un fichier db_config.php sont générés dans le dossier d'export, sécurisés par une clé API aléatoire et une règle .htaccess
  • La carte web interroge la base en direct (avec filtrage par emprise géographique) au lieu d'utiliser un instantané GeoJSON figé
  • Les couches non cochées, ou non connectées à PostgreSQL, sont exportées en GeoJSON statique comme d'habitude
Nécessite un serveur web compatible PHP avec l'extension pdo_pgsql pour héberger le site exporté — un simple hébergement de fichiers statiques ne suffit pas pour ce mode.

7. Table attributaire

Chaque couche vectorielle (shapefile, WFS ou PostgreSQL) possède une icône de table devant son nom dans la légende de la carte. Un clic l'ouvre dans une fenêtre flottante.

  • Déplacez la fenêtre par sa barre de titre, redimensionnez-la par le coin inférieur droit ; plusieurs tables peuvent être ouvertes en même temps
  • Cliquez sur un en-tête de colonne pour trier, saisissez dessous pour filtrer, ou utilisez la recherche globale
  • Survolez une ligne pour mettre l'objet en surbrillance sur la carte ; maintenez Ctrl pendant le survol (ou cliquez la ligne) pour zoomer dessus
  • Exporter en CSV exporte les lignes affichées (après filtrage/tri), séparées par ;, UTF-8 avec BOM pour Excel
  • Les lignes sont paginées (100 par page) pour rester fluide sur les grosses couches
  • L'icône loupe à côté de l'icône de table zoome sur l'emprise de la couche
La table liste les objets chargés dans la page. En mode PostgreSQL dynamique avec filtrage par emprise, seuls les objets de la zone chargée sont affichés.

8. Couches WFS / WMS en direct

  • WFS (vecteur) : une couche connectée à un service WFS dans QGIS est détectée automatiquement. Aucun fichier GeoJSON n'est écrit : la carte web demande les entités (GetFeature, JSON) directement au serveur à chaque chargement. Aucun backend PHP n'est nécessaire. Symbologie, popups, filtrage et table attributaire fonctionnent comme pour toute couche vectorielle.
  • WMS (raster) : les couches connectées à un service WMS sont listées séparément dans Couches WMS dans la boîte de dialogue d'export. Elles sont affichées sous forme de tuiles demandées en direct ; un clic sur la carte interroge le serveur (GetFeatureInfo) et affiche le résultat dans un popup.

Les paramètres de connexion sont lus depuis la couche déjà configurée dans QGIS : rien à ressaisir.

Le serveur OGC doit être accessible depuis le navigateur du visiteur, utiliser https si la carte est servie en https (le contenu mixte est bloqué) et avoir le CORS activé (section suivante). Pour le WFS, le format de sortie application/json doit être disponible (par défaut dans GeoServer).

9. Activer le CORS sur GeoServer (WFS et WMS)

La carte exportée est ouverte depuis une autre origine que votre GeoServer (votre site web, ou http://localhost:PORT avec le serveur local intégré). Le navigateur n'autorise la page à lire les réponses de GeoServer que si celui-ci envoie l'en-tête Access-Control-Allow-Origin.

Service Sans CORS
WFS La couche ne peut pas être chargée (message « bloqué par CORS » dans la légende)
WMS Les tuiles s'affichent, mais l'interrogation au clic (GetFeatureInfo en JSON) est bloquée et bascule sur un cadre HTML

Option A – Administration web (versions récentes de GeoServer) : activez le réglage CORS dans l'interface d'administration web de GeoServer (voir « Enable CORS » dans la documentation GeoServer), puis redémarrez GeoServer.

Option B – web.xml (toutes versions) : modifiez webapps/geoserver/WEB-INF/web.xml, décommentez (ou ajoutez) le filter CORS et son filter-mapping, puis redémarrez.

Version autonome / installeur binaire (Jetty) :

<filter>
  <filter-name>cross-origin</filter-name>
  <filter-class>org.eclipse.jetty.servlets.CrossOriginFilter</filter-class>
</filter>
<filter-mapping>
  <filter-name>cross-origin</filter-name>
  <url-pattern>/*</url-pattern>
</filter-mapping>

WAR déployé dans Tomcat :

<filter>
  <filter-name>CorsFilter</filter-name>
  <filter-class>org.apache.catalina.filters.CorsFilter</filter-class>
  <init-param>
    <param-name>cors.allowed.origins</param-name>
    <param-value>*</param-value>
  </init-param>
  <init-param>
    <param-name>cors.allowed.methods</param-name>
    <param-value>GET,POST,HEAD,OPTIONS</param-value>
  </init-param>
  <init-param>
    <param-name>cors.allowed.headers</param-name>
    <param-value>Content-Type,X-Requested-With,accept,Origin,Access-Control-Request-Method,Access-Control-Request-Headers</param-value>
  </init-param>
</filter>
<filter-mapping>
  <filter-name>CorsFilter</filter-name>
  <url-pattern>/*</url-pattern>
</filter-mapping>
  • N'utilisez qu'une seule méthode : activer le CORS dans l'interface, dans web.xml et/ou dans un proxy inverse en même temps envoie des en-têtes en double et les navigateurs rejettent la réponse
  • * autorise n'importe quel site : en production, remplacez-le par votre ou vos sites, par ex. https://cartes.exemple.org
  • Test : curl -I -H "Origin: https://cartes.exemple.org" "https://votre-geoserver/geoserver/ows?service=WFS&request=GetCapabilities" doit renvoyer un en-tête Access-Control-Allow-Origin

Configuration requise

Composant Configuration
QGIS 3.0 ou supérieure
Navigateur Chrome 90+, Firefox 88+, Edge 90+
Mémoire 4 Go RAM minimum
Connexion Internet (fonds de plan et librairies)

Bonnes pratiques

  • Limitez à 15 couches actives maximum pour des performances optimales
  • Fichiers recommandés < 50 Mo par couche
  • Utilisez le système WGS84 (EPSG:4326) pour vos données
  • Testez l'affichage dans QGIS avant l'export
